# Evaluation

Run `python evaluation/run_eval.py --check` from the repository root. The 19 structured cases in `evaluation/gold_queries.json` cover aggregates, filters, date grouping, CTEs, schema and unsupported routes, ambiguity, adversarial SQL, missing and valid conversation context, and a cache repeat. The harness uploads `data/sample_sales.csv`, uses a scripted fake provider and embeddings, and exercises real FastAPI, RAG, SQLGuard, read-only DuckDB, result profiling, synthesis, cache and response serialization. It writes `evaluation/reports/latest.json` and `latest.md`, or the corresponding `--output` paths. `--check` exits nonzero when any gold case fails. The `latest` files are rolling reports; pass a timestamped `--output` path to keep history.

Execution accuracy is verified analytical cases divided by expected analytical cases. Result accuracy compares row sets after rounding numeric values to six decimals and ignoring order. Schema accuracy checks required base columns against guard-derived references. Security rejection rate counts adversarial cases returned as failed or unsupported. False-block rate counts valid analytical cases not verified. Cache hit rate counts hits among analytical cases. P50/P95 use nearest-rank latency. Repair success counts recovered repairable execution failures; the gold set includes one such case. Phase 3 tests separately cover malicious and repeated repairs. Local Ollama CPU/GPU resource metrics are not measured by this scripted harness.

These scores verify pipeline controls **with scripted model outputs**, not Ollama reasoning quality. To evaluate a local model, extend the provider selection and gold set, then report model/version, hardware, and repeated runs separately. CI runs the scripted benchmark without Ollama. Generated timings vary by machine; case expectations and comparison rules are stable.
