# Development

Phase 1 files are `core.py` (settings/app/errors), `routes.py` (HTTP), `service.py` (dataset lifecycle), `adapters.py` (fixed formats), `db.py` (DuckDB lifecycle), and `schemas.py` (catalog responses). Phase 2 adds `providers.py`, `agents.py`, `rag.py`, `query_models.py`, and `query_service.py`. Phase 3 adds `sql_guard.py`, `executor.py`, and `result_ops.py`. Routes remain thin. Frontend `api.ts` owns network calls.

Run `python -m pytest tests -q` from `backend`; tests use fake LLM and embeddings, not live credentials. Run `npm test` and `npm run build` from `frontend`. The build includes TypeScript checks. No separate formatter or linter is configured. To add a provider, implement the two protocols and wire it in `create_app`; keep errors normalized and secrets out of logs. To add a document type, derive it from catalog truth in `catalog_documents()` and extend the index identity if content can change independently of dataset version. To rebuild an index, delete only that dataset's FAISS directory or change its version/model; the next query rebuilds it. To add an agent, give it a focused prompt, typed output, fake-provider test, and orchestrator stage.

For retrieval evaluation, run the Phase 2 tests and inspect `evaluation/phase2_retrieval.json`. For local API smoke testing, configure `backend/.env` with installed Ollama chat and embedding models, upload the sample CSV, then call `/api/query`. Missing model configuration yields 503. Never route generated SQL into `Database.connection()`; it is reserved for trusted ingestion. Run `python -m pytest tests/test_phase3.py -q` for guard and repair regression checks.

Start Ollama with `ollama serve`, inspect available models with `ollama list`, and set `LLM_MODEL` and `EMBEDDING_MODEL` accordingly. `/api/readiness` checks the server and configured model names. Start the backend from `backend` with `python -m uvicorn app.main:app --reload`; start the frontend from `frontend` with `npm run dev`. The normal test suite requires no Ollama. For an optional live check, upload `data/sample_sales.csv` and ask for top regions by revenue through the UI; this is a manual smoke test, not part of CI.

Extend SQL policy in `sql_guard.py` with both rejection and valid-query tests, especially for DuckDB syntax, CTEs and aliases. Add visualization rules in `result_ops.py` and a typed renderer in `frontend/src/App.tsx`. Debug repairs using `query_id`, validation reason codes, repair attempt count and stage timings; SQL and raw provider responses are deliberately absent from logs.
