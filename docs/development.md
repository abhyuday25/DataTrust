# Development

Phase 1 files are `core.py` (settings/app/errors), `routes.py` (HTTP), `service.py` (dataset lifecycle), `adapters.py` (fixed formats), `db.py` (DuckDB lifecycle), and `schemas.py` (catalog responses). Phase 2 adds `providers.py` (LLM/embedding protocols and HTTP adapter), `agents.py` (prompts and agent calls), `rag.py` (documents/FAISS), `query_models.py` (typed contracts), and `query_service.py` (orchestration). Routes remain thin. Frontend `api.ts` owns network calls.

Run `python -m pytest tests -q` from `backend`; tests use fake LLM and embeddings, not live credentials. Run `npm test` and `npm run build` from `frontend`. The build includes TypeScript checks. No separate formatter or linter is configured. To add a provider, implement the two protocols and wire it in `create_app`; keep errors normalized and secrets out of logs. To add a document type, derive it from catalog truth in `catalog_documents()` and extend the index identity if content can change independently of dataset version. To rebuild an index, delete only that dataset's FAISS directory or change its version/model; the next query rebuilds it. To add an agent, give it a focused prompt, typed output, fake-provider test, and orchestrator stage.

For retrieval evaluation, run the Phase 2 tests and inspect `evaluation/phase2_retrieval.json`. For local API smoke testing, configure `backend/.env`, upload the sample CSV, then call `/api/query`. A missing provider deliberately yields 503. Never route generated SQL into `Database.connection()`; Phase 3 must provide the SQL Guard and read-only executor boundary first.
